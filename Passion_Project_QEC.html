Passion Project Launch Plan

QEC Explorer

An open-source, interactive visualization tool that lets anyone see how quantum error correction works — watch errors propagate, decoders compete, and codes protect information in real time. Built with Qiskit. Designed for the world.

The Gap

What exists vs. what doesn't

The quantum error correction ecosystem has powerful research tools — but nothing that makes QEC visually intuitive for students and newcomers.

What already exists

  • qiskit-qec — IBM's open-source QEC framework. Developer-facing, requires deep Python + QEC knowledge. No visualization layer.
  • STIM — Google's fast stabilizer simulator. Command-line tool, outputs raw statistics. No interactive exploration.
  • PyMatching / MWPM decoders — Research-grade decoding libraries. Zero educational scaffolding.
  • IBM Quantum Learning — Excellent Qiskit courses, but QEC coverage is minimal and not interactive.
  • Microsoft QDK for Error Correction — Just announced Jan 2026, full release expected late 2026. Research-focused, not educational.

What's missing (your niche)

  • Visual, interactive QEC — No tool lets you SEE a surface code lattice, inject errors, and watch a decoder correct them in real time.
  • Decoder comparison — No educational tool benchmarks BP vs. MWPM vs. GNN decoders side-by-side visually.
  • Beginner-accessible entry point — Everything assumes graduate-level knowledge. Nothing bridges "I know what a qubit is" to "I understand why error correction matters."
  • A high school student's perspective — All existing tools are built by PhD researchers. Your tool would be built by someone who recently learned this material and remembers what was confusing.
Project Scope

What you're building

A web-based interactive tool with three layers — from accessible to advanced — so it serves both curious beginners and serious students.

1

Visual surface code playground

Interactive lattice where users click to inject X, Y, Z errors on data qubits. Syndrome measurements highlight automatically. Users see how errors create detectable patterns — the "aha moment" of QEC. No code required.

2

Decoder race visualization

Side-by-side comparison of decoding strategies on the same error pattern. Show BP (your research area), MWPM, and a simple lookup decoder. Animate the correction process step-by-step. Highlight where decoders agree and disagree.

3

Interactive Jupyter notebooks

A series of 5-6 guided notebooks using Qiskit that walk users from "what is a stabilizer code" to "how do neural network decoders work." Each notebook includes exercises. Hosted on GitHub, runnable in Google Colab (free, no install).

4

Noise model explorer

Sliders for physical error rate, bias (X vs. Z), and drift — let users see how different noise environments change decoder performance. Directly connected to your research on biased + drifting noise models.

5

"Why QEC matters" explainer

A non-technical landing page explaining quantum error correction's real-world importance — drug discovery, cryptography, materials science. This page is what gets shared on social media and reaches non-physicists.

6

Research connection page

Link your tool to your actual research paper (when published). Explain how the GNN-FiLM decoder you developed relates to what users just visualized. Bridge from education to your contribution to the field.

Phase 1: Foundation
Weeks 1–3 · April 7–27
Build
Set up GitHub repository with README, LICENSE (MIT), and contribution guidelines
Name the project (e.g., "QEC Explorer" or "qec-viz"). Write a compelling README explaining what the tool does and why it matters. Add a CONTRIBUTING.md so others can help. Choose MIT license for maximum openness.
Build
Build the surface code lattice visualization (Feature #1)
This is your MVP. Create an interactive grid using D3.js or plain SVG/Canvas. Users click data qubits to toggle X/Z errors. Syndrome qubits highlight based on stabilizer checks. Start with the [[d,1,d]] rotated surface code for d=3 and d=5. This is the visual foundation everything else builds on.
Technical tip: use STIM's detector error model to compute syndromes efficiently. The lattice is a 2D grid — d3.js force layout is overkill; use a simple SVG grid with click handlers.
Content
Write Jupyter Notebook #1: "What is a quantum error?"
Start from "what's a qubit" and build to "what happens when noise flips a qubit." Use Qiskit to show a simple circuit, inject an error, and measure the result. Include exercises. This is the entry point for complete beginners.
Network

Share your vision. Ask Dr. Raveendran to review technical accuracy. Ask Greg Pitz if he'd be willing to share it with his IBM network once it's ready. Neither request requires much of their time — you're just planting the seed early.
Phase 2: Core features
Weeks 4–7 · April 28 – May 25

Risk Mitigation

What could go wrong

Time crunch with SAT + research

The tool competes with SAT prep (Apr–Jun) and STS drafting (Jun–Oct) for your hours.

Mitigation: The MVP (Feature #1 alone) is viable in ~20 hours of coding. Build incrementally. Even a surface code visualizer with no decoders is impressive. Don't aim for perfection — ship early, iterate.

Low GitHub traction

You build it but nobody finds it. GitHub stars stay in single digits.

Mitigation: The IBM/Qiskit channel is your ace. One share from Greg Pitz or one Qiskit Slack post can drive 50+ stars overnight. Also: even modest numbers are impressive for a high school project. MIT knows GitHub metrics.

Technical scope creep

You try to build a full-featured QEC simulator and never ship.

Mitigation: The interactive lattice (Feature #1) + 2 notebooks is a complete, shippable product. Everything else is a bonus. Ship v0.1 by Week 5 no matter what. "Working and simple" beats "ambitious and unfinished" every time.
